## SoC 验证、参考模型与调试

验证层级、Formal/FPGA/GLS、软硬件协同和系统交叉场景。
### SoC 验证的层级与集成边界
SoC 验证关注的是集成后的系统行为，通常包括 Boot、CPU、地址映射、互连、存储器、Cache、一致性、DMA、中断、外设、时钟复位、低功耗、安全权限、软硬件协同、错误恢复和性能。验证通常按 IP 级、子系统级、SoC 级和软硬件协同逐层展开。SoC 级最常见的问题不是单个 IP 算错，而是集成边界，例如地址映射错误、配置顺序错误、复位不同步、中断路由错误、DMA/Cache 交互和低功耗状态切换。
### 小型 SoC 的基础与交叉场景
小型 SoC 验证应同时覆盖单模块和系统级交叉场景。对于含 RISC-V、32 KB ROM/RAM、Timer、Watchdog、I2C Master、PLL/晶振切换、工作/睡眠模式的系统，基本 testcase 应包括：复位启动、ROM 边界与越界访问、RAM pattern 读写、Timer 正常倒计时/中断/边界值、Watchdog timeout 和喂狗边界、I2C 读写与 NACK/error、PLL 与晶振动态切换、进入/退出 sleep，以及 sleep 下 Timer/WDT 是否继续工作的行为。更有价值的是交叉场景，如 I2C 传输中请求 sleep、CPU 访问 RAM 时切换时钟、Watchdog timeout 与模式切换同时发生。SoC 结构上通常是 CPU、ROM/RAM、Timer/WDT/I2C 通过系统总线互联，外加 CRG、睡眠控制、电源管理和中断控制模块。
### RTL 仿真通过但 FPGA 原型失败，怎么定位？
最后，RTL 仿真通过而 FPGA 原型失败，应该优先归类为 RTL simulation 与 synthesis/hardware mismatch，而不是简单认为“仿真器有问题”。例如：
```system-verilog
always_comb begin
    next_addr = current_addr;
    next_addr[index] = current_addr[index+1];
end
```

这种“先全量默认赋值，再覆盖一个动态 bit”的写法在语法和正常综合语义上都是合法的。综合器通常会把动态索引实现成 decoder + mux：被 `index` 选中的 bit 取新值，其他 bit 保持 `current_addr`。真正的风险通常来自动态索引越界、`index` 含 X、复位/初始化在 RTL 和 FPGA 上不一致、综合器特殊优化或工具 bug，以及 timing/CDC 问题。验证上应加入索引范围断言、`$isunknown()` 检查和“未被选中的 bit 必须保持不变”的断言，并配合 lint、RTL-to-netlist formal equivalence、必要时 gate-level simulation。一个重要判断方法是：若 RTL 与综合网表 equivalence 已经失败，优先查 RTL/综合语义；若 equivalence 通过但 FPGA 仍失败，则应更关注时序、CDC、复位、初始化和实现层问题。
### FPGA 原型与软件仿真各有什么优劣？
FPGA 原型验证的主要挑战是设计规模和跨 FPGA 分割、板间或芯片间 I/O 限制、跨 FPGA 延迟、时钟和复位映射、ASIC 宏单元替代、内部可观测性弱以及长时间布局布线。其主要优势是运行速度高，适合长软件场景；软件仿真则恰好相反，速度慢但可观测性、可控性和调试能力强，适合断言、覆盖率、约束随机、错误注入和自动化回归。
### 形式验证适合哪些问题？
形式验证适合状态空间可控、性质清晰的控制类问题，例如仲裁器互斥和公平性、FIFO 溢出/下溢、协议属性、非法状态、死锁、安全权限、复位控制和 RTL/门级等价性检查。它的优势是可以证明性质对所有合法状态成立，而不是只验证随机激励碰到的路径，但不适合直接对超大 SoC、长软件流程或模拟电路做完整状态空间验证。
### 门级仿真需要什么，能证明什么？
门级后仿通常需要门级网表、标准单元仿真库、Testbench，以及带时序仿真时使用的 SDF；还可能需要 SRAM、PLL、IO 等 IP 模型。零延迟门级仿真主要检查综合后功能、复位和 X 传播；SDF 后仿还会体现单元和互连延迟、setup/hold、recovery/removal、脉宽等时序检查。门级仿真不能代替 STA，因为仿真只覆盖实际跑到的路径，而 STA 系统性分析时序路径。
### 参考模型应该做到什么精度？
参考模型的作用是根据输入生成期望结果，再交给 scoreboard 与 DUT 输出比较。参考模型可分为功能级、bit-accurate、cycle-accurate、transaction-level 等不同精度。验证环境中不应盲目追求“越精确越好”，而应根据被验证功能决定是否需要位精确、周期精确或仅事务级一致。
### 模拟前端 Expected/Actual 不一致怎样排查？
数字配置与模拟前端联合验证出现 expected 与 actual 不一致时，应分层定位：先查复位时序、寄存器默认值、写入和读回，再查配置是否真正传到模拟接口，随后检查模拟稳定时间、采样时刻、符号位、量化、单位和缩放关系。模拟结果通常不适合严格 `==`，应使用绝对误差或相对误差容限。晶体管级模型精确但很慢，因此芯片级回归通常使用 Verilog-A/Verilog-AMS 行为模型、RNM、`wreal`、查找表或数学模型；晶体管级模型主要用于模块级精确验证和行为模型校准。核心思想是“晶体管级保精度，高层模型保速度”。
### 中断进入与返回的软硬件职责
中断流程要分清软硬件职责。进中断时，外设产生 IRQ，中断控制器完成使能判断和优先级仲裁，CPU 在允许响应后由硬件保存最基本的返回状态，如 PC、处理器状态/特权级等，并跳转到中断向量入口；进入 ISR 后由软件保存必要的通用寄存器、识别中断源并处理中断。出中断时，软件先清除外设中断状态，必要时向中断控制器发送 EOI，再恢复软件保存的寄存器，执行 `mret/eret` 等异常返回指令，由硬件恢复 PC、特权级和中断状态。不同架构硬件自动保存的现场不同，例如 RISC-V 通常通过 `mepc/mcause/mstatus` 保存异常信息，其余大量现场由软件维护。
### Watchdog 的超时、喂狗与窗口机制
看门狗本质是独立超时计数器。软件必须在规定时间内喂狗，否则触发中断、NMI 或复位，用于检测程序跑飞、死循环和系统无响应。超时时间既不能短于正常最长任务时间，也不能过长；最好使用独立时钟；不能在固定中断里无条件喂狗，否则主程序失效时仍可能持续喂狗。窗口看门狗进一步规定“过早喂狗”也属于异常。

## 数值表示、位运算与嵌入式 C

补码、浮点特殊值、lowbit、volatile 和 C 基础。
### 有符号补码、扩位与溢出
SystemVerilog 有符号数采用二进制补码表示，扩位时 signed 做符号扩展，unsigned 做零扩展。N 位 signed 范围为 $-2^{N-1}\sim2^{N-1}-1$。有符号加法中，两个同号数相加却得到相反符号，是典型 overflow；减法中，两个操作数异号且结果符号异常也可能溢出。尤其要注意 signed/unsigned 混合运算和表达式位宽：赋值目标更宽并不保证中间表达式不会先溢出，稳妥做法是先显式扩位、统一 signed 属性再运算。
### Float32：规格化、非规格化与特殊值
IEEE 754 浮点数中，规格化数与非规格化数的核心区别在于有效数最高位是否存在隐含的 `1`。以单精度 `float32` 为例，格式为 `1 bit 符号位 S + 8 bit 指数 E + 23 bit 尾数 F`。当 `1 ≤ E ≤ 254` 时是规格化数，数值为
$$
(-1)^S \times (1.F)_2 \times 2^{E-127}
$$
其中最高位的 `1` 不实际存储，因此称为 hidden bit / implicit 1。规格化的本质就是把二进制数写成类似 `1.xxxx × 2^n` 的形式。
当 `E=0` 且 `F≠0` 时是非规格化数（subnormal，也称 denormal），此时不再有隐藏的 `1`，而是
$$
(-1)^S \times (0.F)_2 \times 2^{-126}
$$
注意指数固定按 `1-127=-126` 计算，而不是 `0-127=-127`。非规格化数的主要作用是表示比最小规格化数 $2^{-126}$ 更小、但又尚未小到 0 的数，实现 gradual underflow（渐进下溢）。单精度最小正非规格化数为 $2^{-149}$，而最小正规格化数为 $2^{-126}$。
判断 IEEE 754 特殊值时，最重要的是先看指数域：


| 指数 E | 尾数 F | 含义 |
| --- | --- | --- |
| `00000000` | `0` | `+0 / -0` |
| `00000000` | 非 0 | 非规格化数 |
| `00000001 ~ 11111110` | 任意 | 规格化有限数 |
| `11111111` | `0` | `+∞ / -∞` |
| `11111111` | 非 0 | `NaN` |


正零和负零只由符号位区分，例如 `+0 = 0 | 00000000 | 0...0`，`-0 = 1 | 00000000 | 0...0`。通常 `+0 == -0`，但某些运算可以体现符号差异，例如 `1/+0 → +∞`、`1/-0 → -∞`。无穷大的指数全 1、尾数全 0，符号位决定正负，常见于溢出或非零数除以零。
NaN（Not a Number）的特征是 `E=255` 且 `F≠0`，常见于 `0/0`、`∞-∞`、`∞/∞` 等无有效实数结果的运算。NaN 的重要特性是它不等于任何数，包括自身，因此 `NaN == NaN` 为假，判断 NaN 应使用专门的 `isnan` 类接口。NaN 还可进一步分为 quiet NaN 和 signaling NaN，常见实现中由尾数最高位区分，但具体异常行为取决于 FPU 实现。
几个常见单精度边界值应记住：
$$
\text{最小正非规格化数}=2^{-149}\approx1.4\times10^{-45}
$$
$$
\text{最小正规格化数}=2^{-126}\approx1.175\times10^{-38}
$$
$$
\text{最大有限正数}=(2-2^{-23})\times2^{127}\approx3.403\times10^{38}
$$
最容易混淆的点有三个：`E=0` 不一定是 0，只有 `E=0,F=0` 才是零；非规格化数没有隐藏的 `1`；`E=255` 也不一定是无穷大，只有尾数为 0 才是无穷大，尾数非 0 则是 NaN。
### X&(X-1)、Lowbit 与常见位操作
常见位运算技巧中，最重要的是 `x & (x-1)` 和 `x & -x`。`x & (x-1)` 会清除最低位的那个 `1`，所以不断执行：
```text
while (x != 0) begin
    x &= x - 1;
    count++;
end
```

循环次数就是原数中 `1` 的数量；同时 `(x != 0) && ((x & (x-1)) == 0)` 可判断 `x` 是否为 2 的幂，注意必须显式排除 `x==0`。`x & -x` 利用二进制补码 `-x = ~x + 1`，会只保留最低置位的 `1`，也称 lowbit。其他常见操作包括：`x & (1<<n)` 检查第 n 位，`x | (1<<n)` 置 1，`x & ~(1<<n)` 清 0，`x ^ (1<<n)` 翻转，`x & 1` 判断奇偶。
### Volatile 能保证什么，不能保证什么？
嵌入式 C 中 `volatile` 表示变量可能被当前执行流之外的因素修改，因此编译器不能把访问随意优化掉，典型用于硬件寄存器、中断共享变量、DMA 更新数据等。`volatile` 只限制编译器优化，不保证原子性、线程互斥、多核内存顺序或 Cache 一致性，因此不能把它当作并发同步机制。
### C 寄存器位操作、数组与指针
C 语言寄存器位操作的通用写法是：置位 `reg |= (1U << n);`，清零 `reg &= ~(1U << n);`。若直接访问硬件寄存器地址，应使用 `volatile`，例如 `*(volatile unsigned int *)0x100 |= (1U<<31);`。二维数组部分初始化时，未显式初始化的元素补 0，例如 `int a[2][2]={2,3};` 得到第一行 2、3，第二行全 0；而 `{{2},{3}}` 则每一行只初始化第一个元素。`int (*ptr)[N]` 是“指向含 N 个 int 的数组的指针”，不是数组名。指针 `==/!=` 可用于合法比较，但 `< > <= >=` 只有在同一数组对象范围内比较才有明确语义。`switch` 表达式要求整数或枚举类型，`float` 不可直接用于 `switch`。统计整数补码中 1 的个数，推荐先转 `unsigned int`，再循环执行 `x &= x-1`，每次消掉最低位一个 1。
### 小数为什么会产生浮点表示误差？
十进制小数转二进制可用小数部分反复乘 2、取整数位的方法。0.1 的二进制是无限循环的 0.000110011…，因此有限位浮点数通常只能近似表示。
### 位操作的类型与寄存器副作用
统计和 lowbit 运算优先用合适宽度的无符号类型；移位量必须在位宽范围内。硬件寄存器读改写还需检查 W1C、read-clear、并发更新和访问宽度，不能把 \|= 或 &= 当成所有 MMIO 的通用写法。

## Linux、Makefile 与仿真调试工具

路径、日志、Make变量、格式化打印和多维数组波形。
### Cp 与符号链接的路径关系
Linux 中，`cp 源 目标` 的第一个路径就是源文件。若源路径不是以 `/` 开头，则按当前工作目录解析，当前目录可用 `pwd` 查看。符号链接使用 `ln -s old new` 创建，`new` 保存的是 `old` 的路径；修改 `old` 的内容后，通过 `new` 仍能访问修改后的数据，但如果 `old` 被删除或改名，符号链接会变成悬空链接，无法继续访问原文件。
### 如何统计非重叠字符串出现次数？
Linux 中统计文件里字符串 `10101` 出现次数，并把结果以 `content: 数量` 写入文件，可以简洁写成：
```text
echo "content: $(grep -o '10101' input.txt | wc -l)" > result.txt
```

其中 `grep -o` 会把每个匹配单独输出，`wc -l` 统计匹配数量。需要注意，这种方式统计的是非重叠匹配次数。
### 如何按整行过滤日志？
Linux 中把文件 A 里所有包含字符串 `test` 的整行保存到 B，最直接写法是：
```bash
grep "test" A > B
```

忽略大小写用 `grep -i`；只匹配完整单词用 `grep -w`。
常用 grep 选项：-n 显示行号，-i 忽略大小写，-v 反选，-E 扩展正则，-r 递归，-A/-B/-C 查看上下文。-c 统计匹配行，不是总出现次数。
### Makefile 命令行变量与自动变量
Makefile 中 `$@` 是自动变量，表示当前规则的 target；常见的还有 `$<` 表示第一个 prerequisite，`$^` 表示所有 prerequisite。例如 `gcc hello.c -o $@` 在目标为 `hello` 时，相当于 `gcc hello.c -o hello`。
工程基础题方面，`make TEST=xxx SEED=xxx` 这种命令行变量可在 Makefile 中用 `$(TEST)`、`$(SEED)` 读取；`make run` 中的 `run` 是 target/goal，`$(MAKECMDGOALS)` 可获取命令目标，recipe 内 `$@` 表示当前 target。
### \$sformatf 为什么不能直接照搬 \$psprintf 参数？
SystemVerilog 里，\$sformatf 和 \$psprintf 最容易混淆的点是：\$sformatf 是标准 SystemVerilog 系统函数，它的调用模型是
```text
$sformatf(format_string, arguments...)
```

也就是说，只有第一个参数是格式字符串，后续所有参数都只是给这个格式字符串里的 `%d`、`%x`、`%s` 等格式符提供数据。比如：
```text
$sformatf("%0s\n", "", "row : %08x\n", 5, ...)
```

第一个格式字符串 `"%0s\n"` 里只有一个 `%0s`，因此只会消耗后面的 `""`。再往后的 `"row : %08x\n"`、`5`、`"col..."` 等，并不会继续被当成新的格式字符串解析，而是变成没有对应格式符的多余参数，所以模拟器会报类似：
```text
More arguments than required
```

因此，使用 \$sformatf 时必须把所有格式说明符放进同一个格式字符串中，例如：
```text
string s;

s = $sformatf(
  "row  : %08x\ncol  : %08x\naddr : %08x\ncmd  : %0s\n",
  5, 6, 7, "cmd"
);
```

或者先利用 SystemVerilog 的字符串拼接构造格式字符串，再调用 \$sformatf：
```text
string fmt;
string s;

fmt = {
  "row  : %08x\n",
  "col  : %08x\n",
  "addr : %08x\n",
  "cmd  : %0s\n"
};

s = $sformatf(fmt, 5, 6, 7, "cmd");
```

\$psprintf 则不是标准 SystemVerilog 接口，而是部分模拟器提供的扩展。某些模拟器会把参数列表中后续出现的字符串继续当作格式片段解析，因此下面这种“格式字符串、参数、格式字符串、参数”交替排列的写法可能恰好能工作：
```text
$psprintf(
  "%0s\n", "",
  "row  : %08x\n", 5,
  "col  : %08x\n", 6
);
```

这也是为什么同一段参数用 \$psprintf 看起来正常，而换成 \$sformatf 就异常。关键不是 \$sformatf 有问题，而是 \$psprintf 支持了模拟器特有的非标准行为，这种代码可移植性较差，工程里应优先使用标准的 \$sformatf。
当 \$sformatf 收到多余参数时，某些模拟器除了报警外，还可能继续把这些参数按默认格式打印出来。字符串在 SystemVerilog 底层本质上是字节序列，因此可能被解释成由 ASCII 字节拼成的大整数。例如 `"cmd"` 的 ASCII 是：
```text
'c' = 0x63
'm' = 0x6d
'd' = 0x64
```

组合成：
```text
24'h636d64
```

其十进制值就是：
```text
6516068
```

所以看到那些看似“随机的大数字”时，通常并不是随机值，而是字符串内容被作为 packed byte 数据按整数形式解释后的结果。
核心结论是：\$sformatf 只有一个真正的格式字符串，即第一个参数；后面的参数必须严格与其中的格式说明符匹配。不要把 \$psprintf 的多格式片段扩展行为套到 \$sformatf 上。
### 十六进制显示与多维数组波形
SystemVerilog 中如果只是把数值按十六进制显示，使用格式化符 `%h` 或 `%0h`，例如 `$display("%0h", a)`；其中 `%0h` 会省略前导 0。若需要把十六进制结果保存成字符串，可用 `$sformatf("%0h", a)`。类似地，`%d/%b/%o` 分别表示十进制、二进制和八进制。
Verdi 查看二维/多维数组时，关键不是单纯在 GUI 中展开，而是仿真阶段必须把数组信息写入 FSDB。`$fsdbDumpvars(...)` 中的 `vars` 是 variables 的缩写，主要用于 dump 普通信号和变量；多维数组通常还需要开启 MDA（Multi-Dimensional Array）dump，例如配合 `$fsdbDumpMDA(...)`。若普通信号有波形而二维数组看不到，应优先检查数组是否被 dump，以及 VCS 编译时是否开启了相应的 memory/debug 支持。最核心的记忆就是：`Dumpvars → 普通信号`，`DumpMDA → 多维数组`。
原笔记还提到 +mda、\$fsdbDumpMDA 和 VCS +memcbk，需结合所用版本与 memory/debug 编译配置确认。
