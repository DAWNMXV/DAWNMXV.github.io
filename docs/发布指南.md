# DAWNMX 博客发布指南

日常入口是 `shortcuts/博客助手.command`。在 Finder 中双击它，会在终端打开中文菜单。

## 第一次使用

这台 Mac 已安装 Node.js、项目依赖和 GitHub CLI。首次打开助手，选择 **7：首次登录 GitHub**，按浏览器中的 GitHub 授权流程完成登录。登录信息由 GitHub CLI 管理，发布工具不把 token 写入项目。

如果登录流程询问是否为 Git 配置凭证，可以选择 No；发布命令会单独为这个博客使用 GitHub CLI 的凭证助手。其他项目的 Git 配置保持原样。登录细节可查阅 [GitHub CLI 官方说明](https://cli.github.com/manual/gh_auth_login)。

换一台电脑时，先安装 Node.js 22.12 或更新版本、Git 和 GitHub CLI，然后在源码目录执行：

```bash
git clone --branch astro-source https://github.com/DAWNMXV/DAWNMXV.github.io.git dawnmxv-astro
cd dawnmxv-astro
npm ci
npm run blog -- login
```

## 发一篇新文章

1. 选择 **1：新建草稿**，填写标题和英文地址，例如 `my-new-post`。或选择 **2：导入 Markdown**，把已有的 `.md` 文件拖进终端，再填写英文地址。
2. 编辑 `src/content/posts/my-new-post.md`。导入时会保留正文和代码，自动复制并优化本地图片；原文件与原图片保持完整。
3. 选择 **4：预览博客**。预览包含草稿，浏览器会自动打开。结束预览时在终端按 `Control+C`。
4. 确认正文、图片和摘要后，选择 **3：标记草稿可发布**，输入文章的英文地址。也可以在 Markdown 开头把 `draft: true` 改成 `draft: false`。
5. 选择 **5：检查并发布**。看到“已上线”及博客地址后，发布完成。

也可以直接双击 `shortcuts/预览草稿.command` 或 `shortcuts/发布博客.command`。

新的草稿及其对应配图默认只保留在本机，发布时不会自动提交。已定稿的文章和必要源码会备份到公开的 `astro-source` 分支，生成的网站推送到 `main`，沿用当前 GitHub Pages 发布设置。

## 导入时如何放图片

把图片放在 Markdown 所在目录或其子目录里，例如：

```text
文章材料/
├── 我的文章.md
└── images/
    ├── 示意图.png
    └── 第二张图.jpg
```

Markdown 中这样引用：

```markdown
![示意图](images/示意图.png)
```

支持 PNG、JPG、WebP、AVIF 和 GIF，以及 Markdown 的引用式图片。普通图片会转为最大 1536 像素宽的 WebP，GIF 保留动画；远程 HTTPS 图片地址保留。本地图片会放在 `public/images/posts/文章英文地址/`，正文路径自动改好。

## 命令行使用

在博客源码目录运行：

```bash
# 打开中文菜单
npm run blog

# 新建或导入草稿
npm run blog -- new "文章标题" my-new-post
npm run blog -- import "/完整路径/文章.md" my-new-post

# 定稿、预览、检查与发布
npm run blog -- ready my-new-post
npm run blog -- preview
npm run blog -- check
npm run publish -- --dry-run
npm run publish

# 查看登录环境或线上发布状态
npm run blog -- doctor
npm run blog -- status
```

`--dry-run` 使用本次将提交的源码快照进行检查，不提交、不推送，并恢复原来的暂存区。正式发布在检查成功后才提交与推送；Git 推送采用正常更新，远端源码有新改动时会提示先同步。源码已推送而网站发布失败时，修复后再次发布即可。

发布期间新建或修改的文件会留到下次发布，本次上传以检查过的快照为准。不要同时运行两个发布命令。

## 常见情况

- **文章没有显示**：查看是否仍为 `draft: true`，或 `pubDatetime` 设到了未来。未来日期的文章需要到时重新发布。
- **图片缺失**：检查 Markdown 图片地址，以及图片是否与 Markdown 放在同一个材料目录中。
- **需要先登录**：选择菜单 7，或执行 `npm run blog -- login`。
- **远端源码有新更新**：先保存本地修改，再按提示同步 `astro-source`；可让 Codex 帮忙处理冲突。
- **改写了旧文**：日常发布检查允许正常改写。`npm run verify:migration` 是原始迁移内容的历史校验，专门用于检查迁移基线，日常发布不要求它通过。

## 项目文件

- `tools/blog.mjs`：菜单与新建、导入、定稿、预览、登录入口。
- `tools/publish-blog.mjs`：源码快照检查、Git 提交、网站生成与部署状态确认。
- `tools/import-post.mjs`：Markdown 导入与图片复制、压缩。
- `tools/verify.mjs`：日常文章、图片、链接、目录、公式与搜索检查。
- `publishing.config.json`：博客仓库、分支和网址设置。

维护发布工具后，可运行 `npm run test:publishing` 检查导入、草稿排除、失败恢复和 Git 发布流程。
